# Обновление и обслуживание

---

## Обновление образа

Образ регулярно пересобирается со свежей версией TorrentMonitor и обновлённым Alpine Linux.
Рекомендуется обновляться вместо использования встроенного автообновления приложения.

> Обновляетесь с версии 3.x на 4.0 — сначала прочтите раздел
> [Переход с версии 3.x на TorrentMonitor 4.0](#переход-с-версии-3x-на-torrentmonitor-40) ниже.

### docker run

```bash
# 1. Скачать свежий образ
docker pull alfonder/torrentmonitor:latest

# 2. Остановить и удалить старый контейнер (данные в томах сохранятся)
docker container rm -f torrentmonitor

# 3. Запустить заново с теми же параметрами и томами
docker container run -d \
  --name torrentmonitor \
  --restart unless-stopped \
  -p 8080:80 \
  -v torrentfiles:/data/htdocs/torrents \
  -v db:/data/htdocs/db \
  alfonder/torrentmonitor

# 4. (опционально) удалить устаревшие образы
docker image prune -f
```

### docker compose

```bash
docker compose pull       # скачать свежий образ
docker compose up -d      # пересоздать контейнер на новом образе
docker image prune -f     # (опционально) убрать старые образы
```

> 💾 Перед обновлением сделайте бэкап папки/тома `db` — см.
> **[Тома и постоянные данные](Volumes-and-Data#резервное-копирование)**.

## Переход с версии 3.x на TorrentMonitor 4.0

TorrentMonitor 4 не использует базу данных: темы, учётные данные трекеров и настройки хранятся в
JSON-файлах. В образе они лежат там же, где раньше лежала база, — в `/data/htdocs/db`, поэтому
тома и compose-файл менять не нужно. Данные переносятся автоматически.

1. Сделайте копию папки/тома `db` — см.
   **[Тома и постоянные данные](Volumes-and-Data#резервное-копирование)**.
2. Обновите образ и пересоздайте контейнер с теми же томами и переменными, как описано выше.
   Если в 3.x вы задавали `ENCRYPTION_KEY`, оставьте её.
3. При первом запуске контейнер видит прежнюю базу (в томе есть `tm.sqlite` и нет `config.json`)
   и переносит её в новые файлы программой `tools/convert-db.php`. Ключ для расшифровки прежних
   паролей берётся из `ENCRYPTION_KEY`, а если она не задана — из файла `db_crypt.key`. Файл
   `config.xml`, если он есть, тоже читается.
4. Проверьте результат в логе контейнера:

   ```bash
   docker container logs torrentmonitor
   ```

   Перенос начинается строкой `Converting the TorrentMonitor 3.x database to the new data format...`
   и заканчивается строкой `Conversion finished.` Между ними — отчёт о том, что перенесено.
5. Откройте веб-интерфейс и проверьте темы, трекеры и настройки. Форма первоначальной настройки
   не показывается, пароль для входа остаётся прежним.

Что нужно знать:

- Переносятся темы, учётные данные трекеров, настройки и пароль веб-интерфейса.
- Файлы `tm.sqlite`, `config.xml` и `db_crypt.key` остаются на месте как копия и больше не
  используются. Когда всё проверено, их можно удалить.
- Перенос выполняется один раз. При следующих запусках в томе уже есть `config.json`, и контейнер
  базу не трогает.
- Пароли трекеров и торрент-клиента теперь записаны в `config.json` в открытом виде (права на файл
  `600`). `ENCRYPTION_KEY` нужна только для переноса, после него её можно убрать. Не давайте
  доступ к папке `db` и её копиям посторонним.
- `config.xml` после переноса не читается. Прокси для отдельных трекеров и другие адреса (зеркала)
  трекеров задаются в веб-интерфейсе, в разделе «Трекеры».
- qBittorrent, Transmission и Deluge получают сам `.torrent`-файл, доступ от них к контейнеру
  TorrentMonitor больше не нужен. Synology Download Station и TorrServer по-прежнему скачивают файл
  по ссылке — для них нужен правильный «Адрес TorrentMonitor».
- Пароля по умолчанию `torrentmonitor` больше нет.

### Если перенос не удался

В логе будет строка `Conversion FAILED: TorrentMonitor will start as a new installation. The
database file is untouched.`, а выше неё — причина. База не изменена. Веб-интерфейс в этом случае
открывает форму настройки новой установки. **Не заполняйте её**: после этого в томе появится
`config.json`, и при следующих запусках перенос выполняться не будет. Устраните причину и
перезапустите контейнер — перенос запустится снова.

### Возврат на 3.x

Вернуться на образ с версией 3.x можно, только пока в томе лежат прежние файлы (`tm.sqlite`,
`config.xml`, `db_crypt.key`) или есть их копия. Изменения, сделанные в 4.0, в прежнюю базу не
записываются: после возврата вы увидите данные на момент перехода.

Об изменениях в самом приложении — в
[Вики TorrentMonitor: Обновление](https://github.com/azinchen/TorrentMonitor/wiki/Updating#переход-с-версии-3x-на-40).

## Проверка текущей версии

Версия приложения зашита в метку (label) образа:

```bash
docker container inspect -f '{{ index .Config.Labels "torrentmonitor.app.version" }}' torrentmonitor
```

Полезные метки образа:

| Метка | Содержит |
| --- | --- |
| `torrentmonitor.app.version` | версия приложения TorrentMonitor |
| `torrentmonitor.app.release-date` | дата релиза приложения |
| `org.opencontainers.image.version` | версия сборки Dockerized |
| `org.opencontainers.image.created` | дата сборки образа |

Посмотреть все метки сразу:

```bash
docker image inspect alfonder/torrentmonitor:latest -f '{{ json .Config.Labels }}'
```

## Логи

```bash
docker container logs torrentmonitor        # весь лог
docker container logs -f torrentmonitor     # следить в реальном времени
docker container logs --tail 100 torrentmonitor   # последние 100 строк
```

Журнал последней проверки трекеров показан в веб-интерфейсе в разделе «Состояние» и лежит в файле
`engine.log` в томе `db`. Папка `logs` (`/data/htdocs/logs`) больше не используется: TorrentMonitor 4
в неё ничего не пишет.

## Запуск проверки трекеров вручную

Не дожидаясь расписания cron:

```bash
docker exec torrentmonitor php -q /data/htdocs/engine.php
```

## Очистка

```bash
docker image prune -f         # удалить «висячие» (dangling) образы
docker container prune -f     # удалить остановленные контейнеры
docker system df              # сколько места занимает Docker
```

> ⚠️ Не используйте `docker volume prune`, если не уверены — это может удалить тома с вашими
> данными.

## Перенос на другой сервер

1. Сделайте бэкап тома/папки `db` (и при желании `torrents`).
2. Установите Docker на новом сервере.
3. Восстановите данные в том же пути.
4. Запустите контейнер с теми же томами и параметрами.

Поскольку вся конфигурация хранится в `db/`, приложение поднимется в том же состоянии.
