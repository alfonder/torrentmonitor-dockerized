# Настройка и использование

После запуска контейнера (см. **[Быстрый старт](Quick-Start)**) основная работа ведётся через
веб-интерфейс TorrentMonitor.

> 📖 Эта вики описывает **Docker-контейнер**. Работа с самим приложением — веб-интерфейс,
> настройки, поддерживаемые трекеры, подключение торрент-клиентов, уведомления — описана в
> **[Вики TorrentMonitor](https://github.com/azinchen/TorrentMonitor/wiki)**.

---

## Первый вход

1. Откройте в браузере адрес контейнера, например <http://localhost:8080> (или
   `http://IP-сервера:8080`).
2. Новая установка показывает форму настройки:
   - пароль для входа или работа без защиты паролем;
   - адрес TorrentMonitor;
   - торрент-клиент — по желанию.

   Пароля по умолчанию `torrentmonitor` больше нет. Заполните форму сразу после запуска: пока она
   не заполнена, это может сделать любой, кто откроет адрес контейнера.
3. После этого в томе `/data/htdocs/db` появляются файлы данных (`config.json` и другие).
4. Дальнейшая настройка приложения (учётные данные трекеров, раздачи для мониторинга) — по
   инструкциям из **[Вики TorrentMonitor](https://github.com/azinchen/TorrentMonitor/wiki)**.

> Если том `db` остался от версии 3.x, форма настройки не показывается: данные переносятся при
> первом запуске, пароль остаётся прежним — см.
> **[Переход с версии 3.x](Updating-and-Maintenance#переход-с-версии-3x-на-torrentmonitor-40)**.

> 🔐 TorrentMonitor не предназначен для прямого доступа из интернета без защиты. Если нужен внешний
> доступ, ставьте контейнер за обратный прокси (Nginx Proxy Manager, Traefik, Caddy) с HTTPS и
> аутентификацией.

## Подключение торрент-клиента из контейнера

Сама настройка клиента выполняется в веб-интерфейсе приложения (см.
**[Вики TorrentMonitor](https://github.com/azinchen/TorrentMonitor/wiki)**). При работе в
Docker учитывайте особенности адресации:

- **Клиент на хосте** — в обычном (bridge) режиме сети указывайте IP-адрес хоста, а не
  `localhost`/`127.0.0.1`: изнутри контейнера `localhost` — это сам контейнер. В Docker Desktop
  можно использовать `host.docker.internal`.
- **Клиент в соседнем контейнере** — поместите оба контейнера в общую сеть Docker и обращайтесь к
  клиенту по имени контейнера (например, `transmission`).
- **Общее сетевое пространство** — если контейнер запущен с `network_mode: host` либо делит сетевой
  стек с клиентом (`network_mode: service:vpn` / `container:...` — типично для связок через VPN),
  клиент доступен по `localhost`.
- Пример готовой связки нескольких контейнеров — на странице
  **[TorrentMonitor + TOR + Transmission](TOR-and-Transmission)**.

В обратную сторону доступ нужен не всем клиентам:

- **qBittorrent, Transmission, Deluge** получают сам `.torrent`-файл. Доступ по сети от клиента к
  контейнеру TorrentMonitor им больше не нужен.
- **Synology Download Station и TorrServer** получают ссылку и скачивают `.torrent`-файл сами.
  Для них «Адрес TorrentMonitor» (**Настройки → Общие**) должен открываться с устройства, где
  работает клиент, — указывайте адрес и порт хоста, а не `localhost`.

## Прокси, зеркала и Cloudflare

Всё это задаётся в веб-интерфейсе; файл `config.xml` больше не читается.

- **Прокси для отдельного трекера и другой адрес (зеркало) трекера** — раздел «Трекеры», форма
  трекера.
- **Общий прокси** — **Настройки → Сеть**.
- **Cloudflare** — в **Настройки → Сеть** укажите адрес FlareSolverr или Byparr (обычно это
  соседний контейнер). Решатель должен выходить в интернет с того же IP-адреса, что и
  TorrentMonitor: если TorrentMonitor работает через VPN или прокси, решатель должен работать
  через тот же VPN или прокси.

Подробности — в [Вики TorrentMonitor: Прокси и зеркала](https://github.com/azinchen/TorrentMonitor/wiki/Proxy-and-Mirrors).

## Расписание проверок

Частота проверки трекеров задаётся переменной окружения
**[CRON_TIMEOUT](Environment-Variables#cron_timeout--расписание-проверок)** при запуске контейнера,
а не в веб-интерфейсе. По умолчанию — раз в час.

Чтобы запустить проверку вручную, не дожидаясь расписания, можно выполнить команду движка внутри
контейнера:

```bash
docker exec torrentmonitor php -q /data/htdocs/engine.php
```

## Автообновление приложения

В веб-интерфейсе TorrentMonitor есть функция самообновления (обновление кода самого приложения).

Обновлять приложение лучше через обновление Docker-образа — см.
**[Обновление и обслуживание](Updating-and-Maintenance)**.

## Где хранятся данные

| Что | Где внутри контейнера |
| --- | --- |
| Данные приложения (JSON-файлы): темы, учётные данные трекеров, настройки | `/data/htdocs/db` |
| Скачанные `.torrent`-файлы | `/data/htdocs/torrents` |

Эти пути выносятся в тома — подробнее на странице **[Тома и постоянные данные](Volumes-and-Data)**.
Папка `/data/htdocs/logs` больше не используется.

Корень сайта внутри контейнера — `/data/htdocs/public`. Программа, настройки и данные лежат вне
его и из браузера недоступны; все запросы Nginx передаёт в `index.php`. Адрес `/healthz` для
проверки состояния контейнера работает как прежде.

## Просмотр логов

```bash
docker container logs -f torrentmonitor
```

Журнал последней проверки трекеров показан в веб-интерфейсе в разделе «Состояние» и лежит в файле
`engine.log` в томе `db`.

Если столкнулись с ошибками — загляните на страницу **[Решение проблем](Troubleshooting)**.
